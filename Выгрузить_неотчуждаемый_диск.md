Инструкция позволяет выгрузить подготовленный образ диска виртуальной машины из облачного провайдера для загрузки в MWS Cloud Platform.

**Результат:** qcow2-файл, готовый к импорту в MWS Cloud Platform.

---

## Порядок действий

1. **Создайте полную резервную копию вашей исходной ВМ.** Изменения могут быть необратимы.

2. **Подготовка ВМ для загрузки в MWS Cloud Platform.**
   Запустите `migration-to-mws` на исходной ВМ до любых операций с диском. Скрипты готовят систему к загрузке в KVM: MBR→GPT, VirtIO-драйверы, devnode, BCD, сброс сети.
   Без подготовки операционной системы импортированный диск не загрузится.
   Подробности — в [`0-Документ-клиенту-Windows.md`](0-Документ-клиенту-Windows.md) или [`0-Документ-клиенту-Linux.md`](0-Документ-клиенту-Linux.md).

3. **Выключите ВМ.**

4. **Выгрузите диск** одним из двух способов ниже.

5. **Загрузите qcow2 в S3 MWS**, получите Path-Style PreSigned URL.

6. **Импортируйте образ в MWS** — Compute → Образы → Создать → По ссылке.

---

## Способ 1: инструмент облака (рекомендуется)

Если у облачного провайдера есть готовый инструмент для экспорта дисков в объектное хранилище — используйте его. Пример — **yc-disk-export-tool**.

Инструмент автоматизирует всю цепочку:

- создаёт временную helper-ВМ;
- подключает к ней диск;
- делает образ через `qemu-img`;
- загружает готовый qcow2 в объектное хранилище;
- удаляет временные ресурсы.

Требуется Linux или MacOS. Windows и WSL не поддерживаются.

**yc-disk-export-tool:** <https://github.com/yandex-cloud-examples/yc-disk-export-tool>

**Результат:** qcow2-файл в объектном хранилище. Скачайте его и загрузите в S3 MWS.

---

## Способ 2: вручную, через Linux-ВМ

Если готового инструмента нет — сделайте это через вспомогательную ВМ в этом же облаке. Подход работоспособен, если возможны операции отключения и подключения дисков между ВМ.

Логика:

1. Остановите исходную ВМ.
2. Отключите её загрузочный диск.
3. Поднимите Linux-ВМ в **той же зоне доступности**, что и исходная ВМ.
4. Подключите диск от исходной ВМ к Linux-ВМ как второй.
5. Внутри Linux-ВМ создайте образ диска.
6. Загрузите qcow2 в S3 MWS.

### Команды внутри Linux-ВМ

Проверьте, что диск виден:

```bash
lsblk
```

Диск появится как `/dev/vdb` или похожее имя (не `/dev/vda` — это системный диск Linux-ВМ).

Создайте raw-образ:

```bash
dd if=/dev/vdb of=/mnt/data/windows.img bs=4M status=progress
```

Здесь:

- `/dev/vdb` — подключённый диск от исходной ВМ;
- `/mnt/data/windows.img` — путь, куда сохраняется образ. Убедитесь, что на этом разделе достаточно места: `dd` создаёт файл полного размера диска.

Сконвертируйте в qcow2:

```bash
qemu-img convert -f raw -O qcow2 /mnt/data/windows.img /mnt/data/windows.qcow2
```

`qemu-img convert` сожмёт образ до реального размера занятых данных. Исходный `windows.img` после этого можно удалить:

```bash
rm /mnt/data/windows.img
```

Загрузите `windows.qcow2` в S3 MWS и получите Path-Style PreSigned URL.

### Важно

- Диск и Linux-ВМ должны быть в одной зоне доступности.
- Диск может быть подключён только к одной ВМ одновременно.
- Нужен запас места на диске Linux-ВМ: `dd` создаёт файл полного размера исходного диска.

**Результат:** qcow2-файл, готовый к импорту в MWS.

---

## После экспорта

1. Загрузите qcow2 в S3 MWS, получите **Path-Style PreSigned URL**.
2. В MWS: **Compute → Образы → Создать → По ссылке**. Вставьте URL, укажите тип ОС, размер диска.
3. Создайте ВМ из образа.
4. Настройте сеть и файрвол.
5. Запустите ВМ.

Если ВМ не загрузилась — см. раздел «Если что-то пошло не так» в [`0-Документ-клиенту-Windows.md`](0-Документ-клиенту-Windows.md) или [`0-Документ-клиенту-Linux.md`](0-Документ-клиенту-Linux.md).
